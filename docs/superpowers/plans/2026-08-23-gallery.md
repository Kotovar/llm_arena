# Gallery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Gallery matrix that compares selected successful web-result versions without interpreting follow-ups in the browser.

**Architecture:** A small server-side projection turns existing task-run state and `selectedVersion` into Gallery rows. The React route groups those rows by immutable prompt revision and model, uses SHA-bound screenshot URLs, and starts one existing preview only from a selected detail dialog.

**Tech Stack:** Node/TypeScript, Fastify, SQLite store, React 19, TanStack Query/Router, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-23-gallery-design.md`

## Global Constraints

- Use `selectedVersion` as the sole version-selection contract for Gallery.
- Include only completed web task runs whose selected result has a valid SHA-backed commit and preview-capable fixture.
- Keep screenshots and previews SHA-bound; do not add a mutable workspace path.
- Do not collapse multiple prompt/model task runs into an arbitrary result.
- Add no dependency or persistence schema.
