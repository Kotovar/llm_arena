Тест №10 — Log Analyzer CLI

Название: Build a streaming log analyzer CLI

Краткое описание:
С нуля создать Node.js CLI, который анализирует большой JSONL-файл с HTTP-логами и выводит агрегированную статистику. Файл нельзя целиком загружать в память.

Тег: cli

Категория: Project Creation / Data Processing

Сложность: Hard
Создай с нуля CLI-приложение на Node.js и TypeScript для анализа HTTP-логов.

Входной файл имеет формат JSON Lines: каждая строка является отдельным JSON-объектом.

Пример:

```json
{"timestamp":"2026-09-10T12:00:01Z","method":"GET","path":"/users","status":200,"durationMs":42}
{"timestamp":"2026-09-10T12:00:02Z","method":"POST","path":"/orders","status":500,"durationMs":183}
```

CLI должен запускаться примерно так:

```bash
npm run analyze -- ./logs.jsonl
```

## Что нужно вывести

После обработки файла выведи:

* общее количество корректных записей;
* количество запросов по HTTP method;
* количество ответов по группам:

  * 2xx
  * 3xx
  * 4xx
  * 5xx
* среднее время ответа;
* максимальное время ответа;
* 5 самых часто встречающихся путей;
* 5 самых медленных путей по среднему времени ответа.

Для каждого пути при расчёте среднего времени учитывай все корректные записи этого пути.

## Большие файлы

Программа должна корректно работать с файлами, которые значительно больше доступной памяти.

Не загружай весь файл целиком через `readFile`, `readFileSync` или аналогичный механизм.

Обрабатывай данные постепенно.

## Некорректные строки

Входной файл может содержать:

* пустые строки;
* некорректный JSON;
* JSON без обязательных полей;
* некорректный `status`;
* отрицательный `durationMs`.

Такие строки:

* не должны приводить к падению программы;
* не должны участвовать в основной статистике;
* должны учитываться отдельно как количество пропущенных записей.

## Детерминированный результат

Если несколько путей имеют одинаковое количество запросов или одинаковое среднее время, используй алфавитный порядок пути как дополнительный критерий сортировки.

Это нужно, чтобы результат был воспроизводимым.

## Дополнительный формат вывода

Добавь флаг:

```bash
--json
```

При его использовании результат должен выводиться как валидный JSON без дополнительного текстового оформления.

Без `--json` должен использоваться удобочитаемый текстовый формат.

## Ошибки CLI

Корректно обработай:

* отсутствие аргумента с путём к файлу;
* несуществующий файл;
* невозможность прочитать файл.

В таких случаях:

* выведи понятное сообщение об ошибке;
* заверши процесс с ненулевым exit code.

## Требования

* Node.js;
* TypeScript;
* не использовать внешнюю базу данных;
* не использовать готовую библиотеку анализа логов;
* не загружать весь входной файл в память;
* не хардкодить данные из примеров;
* бизнес-логику анализа желательно отделить от CLI-обвязки;
* проект должен иметь понятные команды запуска и проверки;
* не создавать web-интерфейс.

После реализации самостоятельно проверь приложение на нескольких входных файлах, включая файл с некорректными строками.
Что здесь можно жёстко проверить

Hidden validator может генерировать собственный JSONL и сравнивать --json результат с точным ожидаемым объектом.

Например:

5000 корректных строк
37 повреждённых строк
разные status/method/path

Проверяется:

total
skipped
methods
status groups
average duration
max duration
top paths
slowest paths

Можно отдельно дать файл на сотни мегабайт и следить за памятью процесса. Если модель сделала:

const content = await fs.readFile(file, 'utf8')

функциональные тесты могут пройти на маленьких данных, но memory-тест провалится.

Почему он заметно отличается от остальных

Здесь почти не помогают типичные навыки генерации React-приложений или CRUD:

streaming I/O;
parsing;
агрегация;
CLI UX;
корректные exit codes;
детерминированная сортировка;
работа с повреждённым input;
ограничение памяти;
точность вычислений.

И особенно интересно сравнить локальные модели по размеру решения. Для этой задачи нормальное решение относительно компактное, но модель легко может переусложнить его несколькими слоями классов, command framework и ненужными dependencies.
