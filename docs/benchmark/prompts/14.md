Build a persistent job queue with retries — Very Hard
Модель с нуля создаёт Node.js + TypeScript сервис очереди фоновых задач. Нужны:

persistent storage, например SQLite;
создание job через HTTP API;
состояния pending / running / completed / failed;
несколько workers;
нельзя выполнить одну job одновременно двумя workers;
retry после ошибки;
configurable maxAttempts;
exponential backoff;
timeout выполнения;
восстановление после перезапуска процесса;
job, оставшаяся в running после crash, должна корректно вернуться в обработку;
graceful shutdown;
нельзя потерять job при падении процесса;
API для просмотра состояния и истории attempts;
атомарное получение следующей доступной job несколькими workers.

Hidden validation здесь уже может реально мучить реализацию:

создать 100 jobs
↓
запустить 4 workers
↓
проверить, что каждая выполнена ровно один раз успешно

затем:

job падает два раза
↓
attempt 1 FAIL
attempt 2 FAIL
attempt 3 PASS

потом crash recovery:

worker получил job
↓
процесс принудительно убит
↓
приложение запущено заново
↓
job не потеряна
↓
job снова становится доступна

И гонка:

8 workers одновременно пытаются получить одну pending job

только один должен её забрать.

Вот эта задача уже хорошо проверяет не просто умение писать код, а способность модели спроектировать согласованную систему с состояниями, транзакциями, concurrency и recovery. Я бы именно её сделал первым Very Hard.
