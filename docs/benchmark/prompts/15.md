Тест №15 — Build a Virtualized Spreadsheet

Название: Build a virtualized spreadsheet editor

Краткое описание:
С нуля создать React + TypeScript приложение в виде небольшой электронной таблицы с тысячами ячеек, виртуализацией, формулами, клавиатурной навигацией, выделением диапазонов, undo/redo и сохранением состояния.

Тег: create-frontend

Категория: Project Creation / Frontend Architecture

Сложность: Very Hard
Создай с нуля небольшое приложение электронной таблицы.

Используй React и TypeScript.

Приложение должно запускаться локально стандартной командой из `package.json`.

## Таблица

Таблица должна содержать:

* 10 000 строк;
* 50 колонок;
* заголовки колонок `A`, `B`, `C` ...;
* номера строк;
* редактируемые ячейки.

Не создавай одновременно DOM-элемент для каждой из 500 000 ячеек.

Реализуй виртуализацию или другой подход, при котором в DOM находятся только элементы, необходимые для отображения текущей области таблицы.

Не используй готовую spreadsheet/grid библиотеку.

## Навигация

Пользователь должен иметь возможность выбирать активную ячейку.

Поддержи:

* Arrow Up;
* Arrow Down;
* Arrow Left;
* Arrow Right;
* Tab;
* Shift+Tab;
* Enter.

При перемещении за пределы текущей видимой области таблица должна автоматически прокручиваться так, чтобы активная ячейка оставалась видимой.

## Редактирование

Пользователь должен иметь возможность:

* выбрать ячейку;
* начать редактирование;
* изменить значение;
* подтвердить изменение;
* отменить текущее редактирование через Escape.

Поддержи как текстовые, так и числовые значения.

## Формулы

Если значение начинается с `=`, воспринимай его как формулу.

Минимально поддержи:

* ссылку на ячейку: `=A1`;
* сложение: `=A1+B1`;
* вычитание;
* умножение;
* деление;
* несколько операций в одной формуле.

Пример:

`=A1+B1*2`

Значение ячейки должно автоматически пересчитываться при изменении зависимых ячеек.

Поддержи зависимости между несколькими уровнями формул.

Например:

`A1 = 10`

`B1 = =A1*2`

`C1 = =B1+5`

При изменении `A1` значение `C1` также должно обновиться.

## Циклические зависимости

Приложение не должно зависать при циклических формулах.

Например:

`A1 = =B1`

`B1 = =A1`

В таких ячейках покажи понятное состояние ошибки.

## Диапазон

Пользователь должен иметь возможность выделить диапазон ячеек с помощью Shift + клавиши навигации.

Визуально отличай:

* активную ячейку;
* остальные ячейки выделенного диапазона.

## Copy / Paste

Поддержи копирование выделенного диапазона и вставку табличных данных.

Формат:

* колонки разделены tab;
* строки разделены newline.

При вставке нескольких значений они должны заполнять соответствующий прямоугольный диапазон начиная с активной ячейки.

## Undo / Redo

Поддержи Undo и Redo минимум для:

* редактирования ячейки;
* очистки значения;
* вставки диапазона.

Новый edit после Undo должен очищать Redo history.

## Persistence

Состояние изменённых ячеек должно сохраняться между перезагрузками страницы.

Не сохраняй все 500 000 пустых ячеек.

Храни только необходимые данные.

## Производительность

Приложение должно оставаться пригодным для работы при:

* быстром scrolling;
* переходе к строкам в конце таблицы;
* большом количестве заполненных ячеек;
* изменении значения, от которого зависит несколько формул.

Избегай полного пересчёта и полного рендера всей таблицы при каждом изменении одной ячейки, если это можно предотвратить разумной архитектурой.

## Требования

* React;
* TypeScript;
* не использовать готовую Data Grid или Spreadsheet библиотеку;
* не использовать backend;
* не использовать внешний API;
* состояние данных не должно храниться непосредственно в DOM;
* не создавать 500 000 DOM-ячеек;
* корректно раздели raw значение ячейки и вычисляемое отображаемое значение;
* формулы не должны выполнять произвольный JavaScript через `eval`, `Function` или аналогичный механизм;
* приложение должно корректно обрабатывать некорректные формулы;
* не хардкодь проверки под конкретные координаты из примеров;
* проект должен иметь понятную структуру;
* добавь команды запуска и проверки.

После реализации запусти доступные проверки и самостоятельно проверь основные пользовательские сценарии.
Почему это действительно Very Hard

Здесь модель должна одновременно решить несколько разных задач:

архитектура состояния для 500 000 потенциальных ячеек;
virtualization;
keyboard UX;
scrolling/focus;
parser формул;
dependency graph;
propagation изменений;
cycle detection;
range selection;
clipboard;
undo/redo;
persistence;
React performance.

Причём можно достаточно объективно определить, справилась она или нет.
