Тест №16 — Turn-Based Tactics Game

Название: Build a turn-based tactics game

Краткое описание:
С нуля создать браузерную пошаговую тактическую игру на сетке с перемещением, препятствиями, дальностью атак, противниками с простым AI и условиями победы/поражения.

Тег: game

Категория: Project Creation / Game Development

Сложность: Hard
Создай с нуля небольшую браузерную пошаговую тактическую игру.

Используй TypeScript.

Для отображения можно использовать DOM, Canvas или другую встроенную браузерную технологию.

Не используй готовый игровой движок.

Проект должен запускаться локально стандартной командой из `package.json`.

## Игровое поле

Создай поле размером `10 × 10`.

На поле должны находиться:

* игрок;
* 3 противника;
* непроходимые препятствия;
* несколько клеток укрытия.

Игровые сущности должны находиться на конкретных клетках сетки.

Две живые сущности не могут занимать одну клетку одновременно.

## Игрок

Игрок должен иметь:

* HP;
* очки перемещения;
* дальность атаки;
* урон.

В начале каждого хода очки перемещения восстанавливаются.

Пользователь должен иметь возможность:

* выбрать клетку для перемещения;
* атаковать противника;
* завершить ход.

После использования атаки повторно атаковать в этот же ход нельзя.

## Перемещение

Игрок не должен иметь возможность:

* проходить сквозь препятствия;
* проходить сквозь других персонажей;
* выходить за границы карты;
* перемещаться дальше доступного количества очков движения.

Стоимость перемещения на соседнюю клетку равна 1.

Используй реальный поиск доступного пути по сетке, а не только расстояние между начальной и конечной клеткой.

Если клетка геометрически близко, но отделена препятствиями, персонаж не должен проходить сквозь них.

## Атака

Атаковать можно только живого противника в пределах дальности.

Атака уменьшает HP цели.

Если HP становится меньше или равно нулю:

* противник считается погибшим;
* больше не получает ход;
* его клетка становится свободной.

Нельзя атаковать через непроходимое препятствие.

Реализуй простую проверку линии видимости между атакующим и целью.

## Укрытия

Некоторые клетки являются укрытиями.

Если цель находится в укрытии относительно атакующего, получаемый урон уменьшается на 50%.

Урон не должен становиться отрицательным.

## Ход противников

После завершения хода игрока каждый живой противник получает свой ход.

AI должен:

1. атаковать игрока, если он уже находится в радиусе атаки и виден;
2. иначе попытаться приблизиться к игроку;
3. не проходить через препятствия и других персонажей;
4. не выходить за пределы карты.

AI не обязан быть оптимальным, но его поведение должно быть детерминированным и корректным.

## Очерёдность

Один раунд состоит из:

1. хода игрока;
2. ходов всех живых противников.

После этого начинается следующий ход игрока.

Не допускай ситуации, когда пользователь может выполнять действия во время хода AI.

## Победа и поражение

Победа:

* все противники уничтожены.

Поражение:

* HP игрока становится меньше или равно нулю.

После завершения игры дальнейшие игровые действия должны быть заблокированы.

Добавь возможность начать новую игру.

## Интерфейс

Пользователь должен видеть:

* игровое поле;
* игрока;
* противников;
* препятствия;
* укрытия;
* HP персонажей;
* текущую фазу хода;
* доступные клетки перемещения;
* возможные цели для атаки;
* результат игры.

Интерфейс не обязан быть визуально сложным, но состояние игры должно быть понятно без просмотра консоли.

## Архитектура

Отдели игровую логику от отображения настолько, чтобы основные правила игры можно было проверить без UI.

Предпочтительно иметь отдельные функции или модули для:

* состояния игры;
* поиска пути;
* определения доступных клеток;
* атаки;
* line of sight;
* AI;
* перехода между ходами.

## Требования

* TypeScript;
* не использовать игровой движок;
* не использовать готовую библиотеку pathfinding;
* не использовать внешний API;
* не хардкодить действия AI под единственную стартовую ситуацию;
* игровое состояние не должно храниться исключительно в DOM;
* не использовать случайность для поведения AI;
* не использовать `eval` или аналогичные механизмы;
* проект должен иметь понятные команды запуска и проверки;
* игра должна быть полностью играбельной после запуска.

После реализации запусти доступные проверки и самостоятельно сыграй как минимум один полный сценарий до победы или поражения.

Почему задача хорошая для benchmark

Она проверяет другой набор способностей, чем обычное приложение:

моделирование состояния;
конечный автомат ходов;
pathfinding;
line of sight;
AI;
игровые правила;
синхронизацию UI и логики;
обработку большого количества взаимосвязанных edge cases.

При этом результат можно проверять довольно жёстко.

Hidden validation

Например, pathfinding:

S . # .
. . # T
. . . .

Модель не должна считать расстояние просто через Manhattan distance — нужен настоящий обход препятствия.

Проверяются также:

move through wall            FAIL
move through enemy           FAIL
move outside map             FAIL
move beyond movement points  FAIL
valid path                    PASS

Атака:

enemy in range + visible       PASS
enemy outside range            FAIL
enemy behind wall              FAIL
dead enemy                     FAIL

AI:

player already in range
→ enemy attacks

player outside range
→ enemy moves closer

path blocked
→ enemy ищет другой доступный путь

И отдельно state machine:

player attacks
player ends turn
AI acts
new player turn

В hidden tests можно проверить, что игрок физически не способен сделать второй ход посреди AI phase.

Для визуальной части при ручной оценке будет ещё интересен Original → Result Preview: у этой задачи исходник практически пустой, а после прогона можно одной кнопкой открыть полноценную мини-игру. Для демонстрации возможностей разных локальных моделей такой тест будет особенно наглядным.
