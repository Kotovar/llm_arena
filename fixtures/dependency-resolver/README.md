# Implement dependency resolution order

Категория Algorithm / Reasoning, сложность Medium. Промпт —
[docs/benchmark/prompts/07.md](../../docs/benchmark/prompts/07.md).

Планировщик задач с зависимостями. Публичный API и классы ошибок уже заданы, чтобы модель не
придумывала свой контракт. Исходная реализация проходит по списку один раз и берёт задачи,
чьи зависимости уже выполнены, — на цепочке, заданной в обратном порядке, она сдаётся, а
неизвестные зависимости и циклы не замечает вовсе.

Зависимостей нет: TypeScript исполняет сам Node, тесты — на `node:test`.

## Состояние fixture

| Проверка | Ожидание |
| --- | --- |
| Существующие тесты | `pass` — базовые случаи работают |
| Порядок, ошибки и края (скрытая) | `fail` — реализация неполная |

Сверяется командой `./scripts/verify-fixture dependency-resolver`.

## Что проверяет скрытая проверка

Порядок как свойство, а не как строку: каждая задача ровно один раз и после всех своих
зависимостей. Плюс ромб, несвязанные графы, повторяющиеся зависимости, пустой список,
неизменность входных данных и граф из тысячи задач цепочкой в обратном порядке.

Отдельно — детерминированность. Правило задано в самом fixture: при равных правах первым
идёт тот, кто раньше во входном массиве. Без такого правила у задачи много правильных
ответов, и проверить конкретный результат было бы нельзя.

Ошибки проверяются по типу, а не по тексту: неизвестная зависимость и три вида цикла —
простой, длинный и зависимость от себя.

## Эталонное решение

`solution/resolveOrder.ts` — обход в глубину с отслеживанием пути. Модель его не видит.

```bash
cp solution/resolveOrder.ts fixture/src/resolveOrder.ts   # во временной копии
```

Валидных решений больше одного: обход в ширину с подсчётом входящих степеней тоже проходит,
если сохраняет правило детерминированности.
