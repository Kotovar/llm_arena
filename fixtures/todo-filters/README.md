# Add filtering to a task list

Категория Feature, сложность Easy. Промпт —
[docs/benchmark/prompts/13.md](../../docs/benchmark/prompts/13.md).

Маленький список задач на чистых ES-модулях вместо React из исходного промпта. Стор
(`src/todos.js`) уже отдаёт `visible()`, которым пользуется представление, но пока это все
задачи; счётчик под списком считает все задачи. Нужно добавить фильтры «все / активные /
выполненные» и считать видимые.

Скрытым тестам нужен контракт, поэтому он назван в тексте задачи: `setFilter(filter)` и
`getFilter()` у стора, `visible()` отдаёт задачи под фильтром, `footerText` считает видимые.
Больше ничего не задано — кнопки, разметку и стили модель делает сама.

Задача — кандидат для метрики overthinking: правильное решение — пара десятков строк.

## Состояние fixture

| Проверка | Ожидание |
| --- | --- |
| Существующие тесты | `pass` |
| Фильтры, счётчик и пустые состояния (скрытая) | `fail` — фильтров нет |

Сверяется командой `./scripts/verify-fixture todo-filters`.

## Что проверяет скрытая проверка

Фильтр по умолчанию, переключение туда и обратно со счётчиком, неизменность самих задач
(`list()` отдаёт все), фильтр продолжает действовать после отметки и добавления, смена
фильтра оповещает подписчиков (иначе страница не перерисуется), пустые состояния: нет
подходящих задач и пустой список под каждым фильтром.

Проверено на неверных решениях: счётчик считает все задачи, смена фильтра не оповещает,
фильтр режет `list()` — каждое роняет хотя бы один тест.

Кнопки на странице тесты не проверяют — это видно в превью.

## Эталонное решение

`solution/` — `todos.js` (фильтр и предикаты), `app.js` (счётчик по видимым, кнопки
`aria-pressed`) и `index.html` (три кнопки). Модель его не видит.

```bash
cp solution/todos.js solution/app.js fixture/src/ && cp solution/index.html fixture/   # во временной копии
```
