# Fix CSV parsing of quoted fields

Категория Debugging, сложность Medium. Отдельного файла промпта в `docs/benchmark/prompts/` нет.

Импорт контактов из CSV. `parseCsv` в `src/csv.ts` делит текст по переводам строк, строки — по
запятым и снимает кавычки регулярным выражением. На простых строках это работает, а на полях в
кавычках ломается: запятая внутри кавычек делит поле, `""` не превращается в одну кавычку,
перевод строки внутри кавычек рвёт запись, пустое поле `""` остаётся двумя кавычками (регулярное
выражение требует хотя бы один символ). Формат описан в doc-комментарии к `parseCsv` — это и
есть контракт; причина бага ничем не помечена.

Потребитель — `importContacts` в `src/contacts.ts` (заголовок, порядок столбцов, обрезка,
email в нижнем регистре, пропуск строк без email) и `src/cli.ts`, который печатает контакты из
`contacts.csv`. Превью нет: задача про одну функцию, судится по патчу и выводу CLI.

Зависимостей нет: TypeScript исполняет сам Node, тесты — на `node:test`.

## Состояние fixture

| Проверка | Ожидание |
| --- | --- |
| Существующие тесты | `pass` — простые строки, CRLF, пустые строки и импорт работают |
| Поля в кавычках разбираются по формату (скрытая) | `fail` — баг на месте |

Сверяется командой `./scripts/verify-fixture csv-quoted-fields`.

## Что проверяет скрытая проверка

`validation/quoted-fields.test.ts` — по отдельному тесту на каждый сценарий промпта: запятая
внутри кавычек, `""` внутри кавычек (в том числе поле из одной кавычки и кавычка на краю),
перевод строки внутри кавычек (`\n` и `\r\n` сохраняются как есть, пустые строки внутри
кавычек не выбрасываются), пустое поле `""` (в том числе строка только из них). Плюс все
случаи вперемешку, простые случаи как регрессия и импорт контактов через `importContacts` —
чтобы разобранные значения доходили до потребителя.

Данные в проверке свои, не из `contacts.csv`: хардкод примера не пройдёт. Обход в
`contacts.ts` вместо правки парсера проваливает тесты на `parseCsv` напрямую.

## Мутанты эталона

Каждый — копия `solution/csv.ts` с одной правдоподобной ошибкой. Скрытая проверка падает на
всех; видимые тесты ловят только m6 и m7.

| Мутант | Ошибка | Упавших скрытых тестов |
| --- | --- | --- |
| m1 | `""` внутри кавычек закрывает поле вместо кавычки | 3 из 7 |
| m2 | перевод строки внутри кавычек завершает запись | 3 из 7 |
| m3 | `""` в начале поля считается экранированной кавычкой, а не пустым полем | 4 из 7 |
| m4 | запятая делит поле и внутри кавычек | 3 из 7 |
| m5 | «почти правильное» решение: разбивка по строкам, split по запятым вне кавычек (lookahead), снятие кавычек и замена `""` | 3 из 7 |
| m6 | строка из пустых полей считается пустой и пропускается (`"","",""`) | 1 из 7 |
| m7 | пустые строки и перевод строки в конце дают пустую запись | 2 из 7 |

## Что оценивать вручную

- Правка в `src/csv.ts`; `contacts.ts` не обрастает обходами (склейкой полей, заменой кавычек).
- Разбор за один проход по символам или эквивалентный; без регулярного выражения на всю строку,
  которое квадратично или ломается на переводах строк.
- Поведение на незакрытой кавычке контрактом не задано и не проверяется — любое разумное.
- Модель не добавила зависимость (csv-parse и т. п.) и не поменяла сигнатуры.

## Эталонное решение

`solution/csv.ts` — конечный автомат по символам. Модель его не видит.

```bash
cp solution/csv.ts fixture/src/csv.ts   # во временной копии
```

Валидных решений больше одного, один-в-один с эталоном результат не сравнивается.
