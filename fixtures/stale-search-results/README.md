# Fix stale search results

Категория Debugging, сложность Medium. Промпт — [docs/benchmark/prompts/01.md](../../docs/benchmark/prompts/01.md).

Поиск пользователей с асинхронным бэкендом. Чем уже запрос, тем быстрее ответ, поэтому при
быстром вводе ответ на предыдущую строку приходит позже ответа на текущую и перезаписывает
результаты. Правильная правка — несколько строк в `src/search.js`.

Зависимостей нет: TypeScript исполняет сам Node, тесты — на `node:test`.

## Состояние fixture

| Проверка | Ожидание |
| --- | --- |
| Существующие тесты | `pass` — неродственное поведение цело |
| Устаревший ответ не перезаписывает результаты (скрытая) | `fail` — баг на месте |

Сверяется командой `./scripts/verify-fixture stale-search-results`.

## Что отсекает скрытая проверка

Промпт прямо называет debounce неправильным решением: он не устраняет гонку, а глушит
первый запрос. Проверка ловит его тремя способами сразу.

1. **Пауза между вводами — 500 мс, разница задержек бэкенда — 900 мс.** Debounce короче
   паузы пропускает оба запроса, и гонка воспроизводится как на исходном коде.
2. **Индикатор загрузки на каждый ввод.** Debounce, отложенный вместе с индикатором,
   показывает его один раз вместо двух.
3. **Результат последнего ввода не откладывается.** Запас в бюджете втрое больше настоящей
   задержки бэкенда, так что медленная машина проверку не завалит, а debounce длиннее паузы —
   завалит.

Проверено на реализациях с задержкой 200, 300, 450, 600 и 900 мс: все падают. Эталонное
решение и исходный код дают устойчивый результат в обе стороны, включая прогон при полностью
загруженном процессоре.

Это не доказательство, что обойти проверку нельзя. Последнее слово остаётся за человеком:
автоматические проверки и вердикт разведены намеренно, и пройденные тесты сами по себе PASS
не означают.

## Эталонное решение

`solution/search.js` — версия `src/search.js` с правкой. Модель её не видит; она нужна, чтобы
убедиться, что скрытая проверка на исправленном коде проходит:

```bash
cp solution/search.js fixture/src/search.js   # во временной копии, не в репозитории
```

Валидных решений больше одного, один-в-один с эталоном результат не сравнивается.
