# Implement paginated user loading

Категория API Integration, сложность Medium. Промпт —
[docs/benchmark/prompts/05.md](../../docs/benchmark/prompts/05.md).

Экран списка пользователей. В исходном промпте проект на React; здесь, как и у остальных
фронтовых fixture, — чистые ES-модули, которые одинаково исполняют браузер и Node.

- `src/api.js` — клиент API `getUsers({ page })` → `{ users, page, hasNextPage }`. Бэкенд
  эмулируется: 23 пользователя по 5 на странице, задержка ответа, третья страница с первой
  попытки отвечает ошибкой.
- `src/users.js` — контроллер: получает клиент параметром и отдаёт представлению состояние
  `{ users, loading: "initial" | "more" | null, error, hasMore }`. Первая страница и повтор
  после её ошибки работают, `loadMore` — заглушка.
- `src/app.js` — представление уже готово: кнопки «Показать ещё» и «Повторить» зависят от
  состояния. Модели его трогать не нужно.

Задача не на отладку: исходный проект не сломан, он просто не догружает страницы.

## Состояние fixture

| Проверка | Ожидание |
| --- | --- |
| Существующие тесты | `pass` — первая страница и повтор после её ошибки |
| Догрузка, повторы, ошибки и дубликаты (скрытая) | `fail` — `loadMore` ничего не делает |

Сверяется командой `./scripts/verify-fixture users-pagination`.

## Что проверяет скрытая проверка

Клиент подменяется управляемым: каждый запрос висит, пока тест не ответит или не уронит его,
поэтому проверяются последовательности, а не счастливый путь. Методы контроллера тест не
ждёт — зависший промис дал бы таймаут вместо честного падения.

- следующая страница добавляется к загруженным;
- `loading` различает первую и следующую загрузку, во время догрузки список на месте;
- повторный `loadMore`, пока идёт запрос, и `loadMore` во время загрузки первой страницы
  запросов не отправляют;
- после `hasNextPage: false` запросов нет;
- ошибка следующей страницы оставляет список, `retry` запрашивает ту же страницу, дальше
  догрузка продолжается со следующей;
- повтор после ошибки первой страницы не ломает догрузку;
- пользователь на границе страниц не дублируется;
- число страниц берётся из ответа API: четыре страницы разного размера.

Проверено на мутантах эталона: без защиты от двойного клика, без дедупликации, замена
списка вместо добавления, повтор не той страницы, ошибка стирает список, `hasMore`
игнорируется — каждый роняет хотя бы один тест.

## Эталонное решение

`solution/users.js` — номер последней загруженной страницы и одна функция `load(page)`,
через которую идут первая страница, догрузка и повтор. Модель его не видит.

```bash
cp solution/users.js fixture/src/users.js   # во временной копии
```

Над-инженерия здесь заметна по диффу: кеш страниц, отдельный data-layer или машина состояний
для задачи, которая решается десятком строк в `users.js`.
