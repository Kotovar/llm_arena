# Implement undo and redo history

Категория Feature Implementation / State Management, сложность Medium. Промпт —
[docs/benchmark/prompts/02.md](../../docs/benchmark/prompts/02.md).

Рабочий редактор списка: добавление, удаление, переименование и перенос элементов. Всё
работает, отмены и повтора просто нет. Переходы состояния уже чистые, так что решение —
локальное расширение, а не переписывание архитектуры.

Зависимостей нет: TypeScript исполняет сам Node, тесты — на `node:test`.

## Состояние fixture

| Проверка | Ожидание |
| --- | --- |
| Существующие тесты | `pass` — редактор полностью рабочий |
| История отмены и повтора (скрытая) | `fail` — возможности ещё нет |

Это fixture типа «нет нужной возможности», а не «есть баг»: исходное состояние корректно, и
`baseline` это фиксирует.

Сверяется командой `./scripts/verify-fixture list-editor-history`.

## Что проверяет скрытая проверка

Последовательности действий, а не наличие двух методов. Отмена трёх разных изменений подряд и
повтор их в обратном порядке. Новое изменение после отмены стирает возможность повтора.
Глубина истории ровно двадцать состояний: после двадцати пяти изменений двадцать первая
отмена уже ничего не делает. Начальная загрузка не отменяется и сбрасывает историю. Отмена и
повтор на пустой истории ничего не ломают. Редактор продолжает работать после отмены.

Отдельная проверка требует одну историю на состояние редактора, а не свою на каждый тип
действия: отмена должна идти в обратном порядке действий вне зависимости от их вида.

Контракт начальной загрузки записан в самом `src/editor.ts`, чтобы модель не угадывала,
считается ли она пользовательским изменением.

## Эталонное решение

`solution/editor.ts` — прошлое и будущее двумя списками поверх существующих чистых переходов.
Модель его не видит.

```bash
cp solution/editor.ts fixture/src/editor.ts   # во временной копии
```
