# Add regression tests for cart rules

Категория Testing, сложность Medium. Промпт —
[docs/benchmark/prompts/04.md](../../docs/benchmark/prompts/04.md).

Корзина интернет-магазина (`src/cart.ts`) и расчёт итога (`src/pricing.ts`). Код корректен,
но тестов три, и ни одно бизнес-правило из задания ими не защищено. Модель должна написать
тесты, а не код.

Зависимостей нет: TypeScript исполняет сам Node, тесты — на `node:test`.

Превью — отчёт о тестах проекта, а не интерфейс корзины: модель пишет тесты, их и показываем.
`server.mjs` на каждый запрос `/tests.xml` запускает `node --test --test-reporter=junit` в
проекте, `report.js` рисует дерево «файл → группа → тест» с упавшими и их сообщениями. Мутанты
на странице не запускаются — они остаются скрытой проверкой.

## Состояние fixture

| Проверка | Ожидание |
| --- | --- |
| Существующие тесты | `pass` |
| Тесты ловят регрессии (скрытая) | `fail` — исходные тесты не ловят ни одного мутанта |

Сверяется командой `./scripts/verify-fixture cart-regression-tests`.

## Что проверяет скрытая проверка

`validation/mutation-check.mjs` копирует рабочий каталог, заменяет `src/` на исходник из
`validation/original-src/` и запускает `node --test`: все тесты модели должны пройти. Затем
то же для девяти мутантов — исходник с одной правдоподобной регрессией:

| Мутант | Правило |
| --- | --- |
| `min-zero` | количество не меньше 1 |
| `no-max` | количество не больше 10 |
| `max-eleven` | то же, граница: 11 уже нельзя |
| `add-ignores-existing` | повторное добавление не выводит за 10 |
| `last-unit-keeps-line` | последняя единица убирает позицию |
| `promo-for-all` | скидка только на товары акции |
| `negative-total` | итог не отрицательный |
| `set-touches-others` | изменение количества не трогает другие позиции |
| `remove-neighbour` | удаление не трогает другие позиции |

Проверка проходит, только если пойманы все девять; вывод показывает счёт
`Mutations caught: N / 9` и пропущенных поимённо.

Исходник берётся из `original-src/`, а не из `src/` рабочего каталога: иначе модель могла бы
подогнать production-код под свои тесты. Если модель его всё же меняла, вывод об этом
сообщает. **`original-src/` — копия `fixture/src/`: при правке fixture обновлять обе.**

Каждый мутант — одна замена строки; если строка не найдена ровно один раз, проверка падает с
ошибкой, а не молча пропускает мутанта.

## Эталонное решение

`solution/tests/cart-rules.test.ts` ловит все девять мутантов. Модель его не видит.

```bash
cp solution/tests/cart-rules.test.ts fixture/tests/   # во временной копии
```

## Что оценивать вручную

Счёт мутантов — необходимое условие, не достаточное. FAIL, если тесты завязаны на
внутренности (приватные поля, порядок вызовов), дублируют один сценарий несколькими почти
одинаковыми тестами или модель правила production-код.
