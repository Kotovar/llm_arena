# Implement a debounce utility

Категория Feature, сложность Easy. Промпт —
[docs/benchmark/prompts/12.md](../../docs/benchmark/prompts/12.md).

Маленький TypeScript-проект: поле поиска (`src/search.ts`) отправляет запрос через
`debounce` из `src/debounce.ts`. Сигнатура и тип `Debounced` уже заданы, а сама функция —
заглушка: вызывает `fn` сразу, `cancel` ничего не делает. Задача проверяет, что модель решит
маленькую задачу и остановится: правильная правка — десяток строк в одном файле.

Зависимостей нет: TypeScript исполняет сам Node, тесты — на `node:test` с подменой таймеров
через `t.mock.timers`. Интерфейса для ревью нет осознанно: судить здесь нужно по патчу, а не
по поведению на экране.

## Состояние fixture

| Проверка | Ожидание |
| --- | --- |
| Существующие тесты | `pass` — нормализация запроса и отправка работают и с заглушкой |
| Серии вызовов, аргументы, this и cancel (скрытая) | `fail` — заглушка не откладывает вызов |

Сверяется командой `./scripts/verify-fixture debounce-utility`.

## Что проверяет скрытая проверка

Серия быстрых вызовов даёт один вызов с последними аргументами и не раньше срока; каждый вызов
перезапускает ожидание; аргументы передаются как есть; `this` берётся от последнего вызова.
`cancel` отменяет ожидающий вызов, безопасен без него и не ломает функцию для дальнейших
вызовов. Две debounce-функции не делят таймер.

Проверено на мутантах эталона: потерянный `this`, пустой `cancel`, общий таймер на модуль и
отсутствие перезапуска — каждый роняет хотя бы один тест.

## Эталонное решение

`solution/debounce.ts` — один таймер в замыкании. Модель его не видит.

```bash
cp solution/debounce.ts fixture/src/debounce.ts   # во временной копии
```
