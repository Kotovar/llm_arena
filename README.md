# LLM Arena

Локальное приложение для сравнения LLM на одинаковых промптах. Поддерживаются GGUF-модели через llama.cpp и OMP, Claude Code и Codex CLI.

## Запуск

Нужны Node.js 24+, pnpm 11+ и настроенные CLI моделей.

```bash
pnpm install
pnpm dev
```

Откройте `http://127.0.0.1:5173`. Backend работает только на `127.0.0.1:3210`.

## Как пользоваться

1. В разделе «Модели» подключите GGUF-файл или облачную модель.
2. Нажмите «Проверить модель», чтобы выполнить короткий реальный запрос.
3. В разделе «Промпты» добавьте задания для сравнения.
4. На странице «Запуск» выберите модель, один промпт или все сразу.
5. Для Claude или Codex выберите доступный уровень мышления.
6. Выберите результат: «Текстовый ответ» или «Готовое web-приложение».
7. Нажмите «Запустить» и следите за прогрессом и выводом агента.

Запуск можно прервать. Результаты сохраняются и доступны после перезапуска приложения.

## Результаты

Для каждого прогона показываются:

- время работы;
- новые входные, кешированные и выходные токены;
- число обращений агента к модели;
- скорость генерации; расчётная скорость Claude/Codex отмечается знаком `≈`;
- ответ агента, изменения файлов и сырые stdout/stderr;
- Preview готового web-приложения;
- ручная оценка и комментарий.

После завершения можно отправить дополнительный промпт: попросить исправить реализацию или уточнить текст. Для web-результата агент продолжит работу в том же workspace. Исходный ответ не перезаписывается — уточнения показываются отдельной историей со счётчиком.

Большое число входных токенов у coding-agent нормально: агент несколько раз обращается к модели и передаёт текущий контекст. «Из кеша» показывает часть этого контекста, которую llama.cpp повторно использовал без полного пересчёта.

Завершённый результат можно удалить отдельно. «Очистить все» удаляет только завершённые, ошибочные и отменённые запуски. Активный запуск сначала нужно остановить.

## Локальные GGUF-модели

Путь к llama-server и стартовые модели задаются в `arena.config.yaml`.

`MoE-слоёв на CPU` соответствует флагу llama.cpp `--n-cpu-moe`: экспертные веса первых N MoE-слоёв остаются в оперативной памяти. `0` не переносит слои на CPU. Увеличивайте значение при нехватке VRAM; это может снизить скорость.

Кнопка «Подобрать VRAM» ищет минимальный стабильный CPU-offload при сохранении заданного резерва VRAM.

## Claude и Codex через прокси

При подключении облачной модели интерфейс предлагает Claude aliases и модели Codex из локального кеша установленного CLI. Полный идентификатор всегда можно ввести вручную. Выбранный перед запуском уровень мышления сохраняется вместе с результатом.

В конфигурации уже есть обычные и proxy-runners. По умолчанию используются:

- `claudep` для Claude Code;
- `codexp` для Codex CLI.

Обычные `claude` и `codex` можно выбрать в «Дополнительных настройках» запуска. Глобальные настройки shell и environment приложение не меняет.

## Где хранятся данные

SQLite и артефакты находятся в `.data/`:

```text
.data/runs/<run-id>/<task-run-id>/
  workspace/
  stdout.log
  stderr.log
  display.log
  diff.patch
  result.json
```

Команды fixtures и runners берутся только из доверенного `arena.config.yaml`. UI не может передать произвольную shell-команду, а дочерние процессы запускаются в отдельных process groups и корректно завершаются при Cancel или остановке приложения.
