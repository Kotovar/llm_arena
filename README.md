# LLM Arena

Локальное приложение для сравнения LLM на одинаковых промптах. Поддерживаются GGUF-модели через llama.cpp и OMP, Claude Code и Codex CLI.

## Запуск

Нужны Node.js 24+, pnpm 11+ и настроенные CLI моделей.

```bash
pnpm install
pnpm dev
```

Откройте `http://127.0.0.1:5173`. Backend работает только на `127.0.0.1:3210`.

## Как пользоваться

1. В разделе «Модели» выберите найденный GGUF-файл или подключите облачную модель.
2. Для локальной модели оставьте автоматический профиль либо настройте параметры вручную. Нажмите «Проверить модель», чтобы выполнить короткий реальный запрос.
3. В разделе «Промпты» добавьте задания для сравнения.
4. На странице «Запуск» отметьте один, несколько или все промпты.
5. Для Claude или Codex выберите доступный уровень мышления.
6. Выберите результат: «Текстовый ответ» или «Готовое web-приложение».
7. Нажмите «Запустить» и следите за прогрессом и выводом агента.

Запуск можно прервать. Результаты сохраняются и доступны после перезапуска приложения.

## Результаты

Для каждого прогона показываются:

- время работы;
- новые входные, кешированные и выходные токены;
- число обращений агента к модели;
- скорость генерации; расчётная скорость Claude/Codex отмечается знаком `≈`;
- ответ агента, изменения файлов и сырые stdout/stderr;
- Preview готового web-приложения;
- оценки «Корректность», «Качество кода», «Визуал» и «Следование заданию» — до 40 баллов за результат;
- общий балл запуска и покрытие оценками;
- кнопка открытия сохранённого workspace в Zed;
- Preview, когда выбранный тип результата его поддерживает.

После завершения можно отправить дополнительный промпт: попросить исправить реализацию или уточнить текст. Для web-результата агент продолжит работу в том же workspace. Исходный ответ не перезаписывается — уточнения показываются отдельной историей со счётчиком.

Большое число входных токенов у coding-agent нормально: агент несколько раз обращается к модели и передаёт текущий контекст. «Из кеша» показывает часть этого контекста, которую llama.cpp повторно использовал без полного пересчёта.

Завершённый результат можно удалить отдельно. «Очистить все» удаляет только завершённые, ошибочные и отменённые запуски. Активный запуск сначала нужно остановить.

В «Сравнении» результаты сопоставляются по одной ревизии промпта. Для каждого результата отдельно доступны переход к карточке и Preview, если он предусмотрен.

## Локальные GGUF-модели

По умолчанию приложение сканирует верхний уровень `models` и показывает обычные файлы `.gguf` в списке. Путь можно изменить в «Настройках» без ручного ввода полного пути при каждом подключении. Символические ссылки и выход за выбранную директорию не разрешены.

Путь к `llama-server` задаётся в `arena.config.yaml`.

`MoE-слоёв на CPU` соответствует флагу llama.cpp `--n-cpu-moe`: экспертные веса первых N MoE-слоёв остаются в оперативной памяти. `0` не переносит слои на CPU. Увеличивайте значение при нехватке VRAM; это может снизить скорость.

Автоматический профиль использует нативный `llama-server --fit`, доступную VRAM и заданный резерв (по умолчанию 750 MiB). Контекст начинается не ниже 4096 токенов. Кнопка «Подобрать под систему» запускает модель, проверяет её готовность, считывает фактическое использование GPU и сохраняет отчёт рядом с моделью. Все параметры — контекст, GPU-слои, Flash Attention, batch, micro-batch, квантизация KV-cache, параллельность и CPU-offload — можно переключить в ручной режим.

## Использование профиля во внешнем агенте

Кнопка «Использовать с OMP» делает выбранную модель активной и создаёт исполняемый файл:

```text
.data/exports/active-model.fish
```

Он содержит уже подобранную модель и аргументы `llama-server`. Универсальный внешний запускатель, например `local-model-server`, может только передавать ему управление:

```fish
#!/usr/bin/env fish
exec /absolute/path/to/llm-arena/.data/exports/active-model.fish
```

Так связка агента не зависит от имени конкретной модели: для неё можно использовать нейтральные имена `omp-local`, `local-model-server` и `omp-local.kdl`, а прежний `omp-ornith` оставить совместимым алиасом. Приложение само не изменяет файлы в `~/.local/bin` и `~/.config/zellij`.

## Claude и Codex через прокси

При подключении облачной модели интерфейс предлагает Claude aliases и модели Codex из локального кеша установленного CLI. Полный идентификатор всегда можно ввести вручную. Выбранный перед запуском уровень мышления сохраняется вместе с результатом.

В конфигурации уже есть обычные и proxy-runners. По умолчанию используются:

- `claudep` для Claude Code;
- `codexp` для Codex CLI.

Обычные `claude` и `codex` можно выбрать в «Дополнительных настройках» запуска. Глобальные настройки shell и environment приложение не меняет.

## Где хранятся данные

SQLite и артефакты находятся в `.data/`:

```text
.data/runs/<run-id>/<task-run-id>/
  workspace/
  stdout.log
  stderr.log
  display.log
  diff.patch
  result.json
```

Команды fixtures и runners берутся только из доверенного `arena.config.yaml`. UI не может передать произвольную shell-команду, абсолютный путь к модели или путь сохранения. Дочерние процессы запускаются без shell, в отдельных process groups и корректно завершаются при Cancel или остановке приложения.
